# Building and releasing the Linux client

Application code is proprietary; see [COPYRIGHT](../COPYRIGHT). Release packages contain compiled application modules and replaceable third-party shared libraries. Never add an open-source license for the application without the owner's approval.

The supported release baseline is Ubuntu 24.04 x86_64 with its system Python 3.12. A binary built on a newer distribution can depend on newer glibc symbols and must not be published as a 24.04 build.

## Local checks

Create an isolated environment and install the pinned build inputs:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r client/requirements-build.txt -r server/requirements.txt httpx
QT_QPA_PLATFORM=offscreen .venv/bin/python -m unittest discover -s tests -v
SPC_BUILD_PYTHON="$PWD/.venv/bin/python" PATH="$PWD/.venv/bin:$PATH" bash scripts/compile-client.sh
bash scripts/build-client-deb.sh 0.3.0~beta.1
```

The compiler needs GCC and patchelf. The build script downloads the matching third-party sources, checks the FFmpeg license configuration, includes their notices, and performs a headless smoke test of the compiled UI and WebP decoder. Do not remove the separate shared libraries or combine them into a sealed executable. Inspect the package before publishing; application `.py` and `.pyc` files must be absent.

## Publication

1. Update the version in `client/main.py`, `server/app.py`, the server dashboard, README and CHANGELOG.
2. Merge the reviewed release change into `main` after the source tests and Ubuntu 24.04 compiled package check pass. Use a clear product-facing squash commit; avoid publishing machine logs, credentials or personal screenshots.
3. Tag that `main` commit, for example `v0.3.0-beta.1`, and push the tag. The release workflow repeats tests and builds on Ubuntu 24.04 before publishing a prerelease.
4. Check that the release has the architecture-specific `.deb`, SHA-256 checksums and corresponding third-party source archive. Verify the downloaded artifact's checksum and compiled self-test.

Beta tags remain prereleases. Source archives automatically generated by GitHub do not grant a license to the application's source code. Repository visibility and application licensing are separate decisions.
